# Mail-action taxonomy + reversibility tiering (research, cited)

**Date:** 2026-07-04 · **Method:** structured research pass (6 angles → 26 primary sources fetched → 106 claims → 25 adversarially verified, **25/25 confirmed, 0 refuted**).
**Purpose:** ground Photon's neutral verb set + the ADR-P005 color-tier taxonomy in the actual protocols, before we lock a `Tier` enum + a verb roadmap. "Name the standard, design to it, cite it."

---

## Headline

The verb taxonomy is well-grounded in primary sources. **ADR-P005's tier table is directionally correct but incomplete** ~~and mis-tiers `trash`~~ **[CORRECTED: the trash "mis-tier" claim was overturned on review — trash STAYS RED; see the erratum below. The provider facts stand.]** The load-bearing architectural split:

- **State-toggle verbs** (read/unread, flag/star, answered, draft) — modeled as reversible keyword/flag/property toggles: JMAP `keywords` (`$seen`/`$flagged`/`$draft`/`$answered`) ↔ IMAP system flags (`\Seen`/`\Flagged`/`\Draft`/`\Answered`) ↔ Gmail system labels (`UNREAD`/`STARRED`) ↔ Graph Boolean props (`isRead`, `flag`). **[Precision note:** the FULL four-surface clean mapping is grounded for **read** only. **Star/flag** maps cleanly on JMAP/IMAP/Gmail, but Graph's `message.flag` is a structured `followupFlag` (`notFlagged`/`flagged`/`complete`, optionally with dates) — NOT a Boolean star; a naive toggle can overwrite completed/scheduled follow-up state, so the Graph arm needs a preservation/mapping decision. **Answered** is grounded on JMAP/IMAP only (no verified Gmail/Graph mechanic), and **draft** is NOT toggleable on Gmail (finding 4) — treat answered/draft as partially-grounded/provider-specific until concrete mechanics are established.**]** **Clean neutral mapping → YELLOW** (fully grounded for read; star with the Graph mapping caveat).
- **Location verbs** (archive, move, trash, snooze) — reversible **but the mechanic diverges sharply**: JMAP/Graph = folder/mailbox membership; Gmail = label add/remove; IMAP = COPY/MOVE relocation. Neutral *verb*, provider-divergent *mechanic* — must be footnoted "no clean mapping."
- **The critical reversibility boundary — two-stage delete:** `trash`/mark-deleted is **recoverable metadata** (Gmail `messages.trash`+`untrash`, 30-day window; IMAP `\Deleted` before `EXPUNGE`; JMAP trash-mailbox removal) whereas **permanent removal is genuinely irreversible/BLACK** (Gmail `messages.delete` "cannot be undone"; IMAP `EXPUNGE`; Graph `permanentDelete`; JMAP destroy-when-in-no-mailbox).

## Verified findings (all high-confidence, 3-0, primary-sourced)

1. **State verbs map cleanly, are YELLOW** ~~read/flag/answered/draft = reversible toggles across JMAP keywords / IMAP flags / Gmail labels / Graph props~~ **[CORRECTED: the cross-provider claim was overbroad — see the precision note in the headline split. Grounded: READ across all four; STAR/FLAG on JMAP/IMAP/Gmail (Graph `flag` is a structured `followupFlag`, needs a mapping decision); ANSWERED on JMAP/IMAP only; DRAFT not toggleable on Gmail. Do not cite this finding as grounding a four-provider YELLOW class beyond read.]** RFC 8621 explicitly documents the `$`-keyword ↔ `\`-flag mapping. (RFC 8621, RFC 9051, MS Graph message)
2. **Location verbs (archive/move) are reversible but mechanic-divergent** → "no clean mapping." JMAP Email id does NOT change on move (edit `mailboxIds`, no first-class move verb; `role` gives inbox/archive/trash/junk/drafts/sent, max one mailbox per role); Gmail archive = `removeLabelIds:[INBOX]` (labels are tags, not folders); IMAP = COPY/MOVE preserving Internal Date. (RFC 8621, RFC 9051, RFC 6851, Gmail labels/modify)
3. **Two-stage delete:** trash = reversible metadata; permanent-delete/EXPUNGE/destroy = BLACK. (Gmail trash/delete, RFC 8621, RFC 9051)
4. **Gmail system-label toggleability is verb-determining:** INBOX/UNREAD/STARRED/SPAM/TRASH/IMPORTANT are manually applicable (mechanically reversible **[SUPERSEDED note 2026-07-21: mechanical toggleability does NOT itself imply YELLOW — trash is toggleable yet stays RED per P005's compensatable definition; see erratum]**); **DRAFT/SENT are auto-applied and CANNOT be toggled** — draft/sent state does not map to the label-toggle mechanic. (Gmail labels guide/reference)
5. **A class of one-way / move-based keywords the sketch omits:** RFC 5788 `$MDNSent`/`$Forwarded` "once set SHOULD NOT be cleared" (**one-way** — less reversible than a plain toggle); `$muted`↔`$followed` (mute = reversible client-set keyword, mutually exclusive, NOT a mailbox move — **[precision note: the keyword SET/CLEAR is reversible, but RFC 9979 lets these keywords drive ONGOING automatic behavior on future messages (mute may archive/trash/mark-read later replies; follow may bypass filtering/notify) — rule-like consequences, so keyword-toggle reversibility does NOT itself ground a YELLOW tier]**); the `Snoozed` role mailbox (RFC 9979 registers the mailbox attribute/storage semantics; **the snooze/unsnooze mechanism itself is expressly NOT defined by the RFC — it rests on the still-open snooze draft**). Adds **mute, snooze, follow/watch, forwarded, mdn-sent** verbs. (RFC 5788, RFC 9979, snooze draft)

## Verdict on the ADR-P005 sketch tier-table

**Directionally correct, with concrete corrections owed:**
- ✅ **GREEN** (scan/search/list/preview) — correct; all read-only (JMAP get/query, IMAP SEARCH/FETCH, Gmail list, Graph GET).
- ✅ **YELLOW metadata core** (archive, label/unlabel, move, mark read/unread) — correct as reversible metadata; **but `archive` must be footnoted mechanic-divergent** (Gmail label-removal vs IMAP/JMAP/Graph folder move).
- ✅ **BLACK** (send, reply, forward, permanent-delete, filter-deletion, credential-mutation) — correct; outbound/irreversible; permanent-delete verbatim "cannot be undone."
- ~~❌ MIS-TIER — `trash` is in RED but is reversible metadata … It is nearer YELLOW~~ **[CORRECTED — recommendation OVERTURNED, see the erratum directly below; do not cite this line as a re-tier ground. The recoverability FACTS (untrash / `\Deleted`-clear / re-add-to-mailbox) remain valid and become RED *rationale*.]**
  - **[ERRATUM — this recommendation is OVERTURNED; the provider FACTS above stand.]** ADR-P005 *defines* RED as "socially reversible / compensatable" — i.e. RED already IS the reversible-with-compensation tier, and trash (time-bounded, recoverable-with-effort, out of normal reach) is its textbook case; the re-tier premise misread RED as "irreversible." ADR-P007's heavier trash-snapshot class concurs. Also target-state-dependent: a trashed DRAFT is unrecoverable (official Gmail guidance), so generic trash must stay conservative and `discard-draft` is a separate verb. **Trash stays RED**; the finding becomes a tier-definition clarification for the amendment. See ADR-P005 in `docs/adr/`.
- ❌ **MISSING verbs:** mute (`$muted`), snooze (`$Snoozed`), follow/watch (`$followed`), mark-answered (`$answered`), forwarded (`$Forwarded`), mark-spam/not-spam, mark-important, save/discard-draft, empty-trash — and the recognition that **one-way keywords (`$MDNSent`/`$Forwarded`) are not plain YELLOW toggles.**

## Gaps & caveats (do NOT treat these as settled)
- **Not source-grounded in this pass (need their own grounding before final tiering):** unsubscribe (RFC 8058 one-click), block/unblock sender, create/modify/delete filter/rule (Sieve / RFC 9661 JMAP-Sieve / Graph messageRules), mark-spam/not-spam, mark-important. Open question: does filter-creation (RED) vs filter-deletion (BLACK) split hold across providers?
- **The 4-tier model itself is *our* framework, not provider wording** — providers document reversibility *facts*; the facts→tier mapping is inference. The requested prior-art validation (MCP annotations `readOnlyHint`/`destructiveHint`/`idempotentHint`; OAuth `readonly`/`modify`/`full` scopes) produced **no surviving verified claims** — so the 4-tier model is not yet *externally validated* against those taxonomies (open question: do they suggest a different number of tiers?).
- **Provider-dependent reversibility:** mark-spam (Gmail SPAM label reversible vs providers where spam-report trains a filter + sends a report); archive (metadata everywhere but a destructive relocation on IMAP if the source copy is the only one). These verbs' tiers are genuinely provider-dependent.
- **Sub-tier question:** should one-way keywords (`$MDNSent`/`$Forwarded`) get a sub-tier between YELLOW and RED (reversible-in-storage but semantically set-once)?
