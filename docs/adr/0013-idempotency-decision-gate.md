# ADR-P013: The idempotency-decision gate (one status-aware decision point)

**Status:** Accepted


**Decision.** The idempotency contract for the durable mutation engine (`aruna`) lives in ONE place: a pure, status-aware classifier — `classify(command, &log) -> Decision` — consulted by `execute()`, `record()`, and `recover()` alike. No call site re-derives same-key semantics.

- **`Decision` is a typed, status-classed enum, matched exhaustively at every call site — and call sites MUST NOT branch on raw `IntentStatus`.** Encoding the status *into* the variants is what makes the exhaustive match load-bearing; a wildcard over an embedded raw status would defeat it. Variants: `Fresh`; `Conflict`; `InProgress { state: Pending | Undoing | EvidenceSnapshotWritten }`; `TerminalReplay { terminal: Applied | Undone | Failed }`. The classifier itself matches `IntentStatus` exhaustively, so a future state is a *compile error* there until mapped.
- **Idempotency fingerprint (defined, not implicit).** "Identical payload" = the full `Command` identity **including the `ActionEnvelope`** (account, facet, action, principal, epoch, evidence_ref, snapshot_ref, tier). Security-relevant: a same-key submission under a *different principal/epoch* is a `Conflict`, not a replay — you cannot replay another principal's key.
- **Replay truth table** (the normative contract — `fingerprint x existing-status -> decision / execute() outcome`):

  | Existing status | Identical fingerprint -> decision (and `execute()` outcome) | Different fingerprint |
  |---|---|---|
  | _(absent)_ | `Fresh` -> reserve `Pending`, dispatch | `Fresh` (no prior payload to compare) |
  | `Pending` | `InProgress` — no re-record, no re-dispatch; **outcome: a distinct in-flight / recovery-owns-it result, never `Ok`** | `Conflict` -> reject + audit |
  | `Undoing` | `InProgress` (undo in flight) — same in-flight outcome | `Conflict` |
  | `EvidenceSnapshotWritten` _(reserved)_ | `InProgress` | `Conflict` |
  | `Applied` | `TerminalReplay` -> `Ok` no-op | `Conflict` |
  | `Undone` | `TerminalReplay` -> `Ok` no-op, **never re-apply** | `Conflict` |
  | `Failed` _(reserved in M0)_ | `TerminalReplay` -> **return the failure / dead-letter outcome (`Err`), never silent `Ok`, no re-dispatch** | `Conflict` |

- **Return-signal contract (the audit trail must never lie — in EITHER direction).** `execute()` MUST NOT return `Ok` for an intent that has not terminally *succeeded*. `InProgress` returns a distinct *not-yet-succeeded* signal (the Stripe/brandur `409`-while-processing analog); an identical retry of a `Failed`/dead-lettered intent returns the failure outcome (`Err`), never `Ok`. Silent false-success is the same disqualifying audit-integrity class as the silent mutation / resurrection this ADR exists to kill.
- **`record()` never regresses status OR `seq`.** An identical re-record must NOT reset any existing row's status back to `Pending` (a drift defect observed in practice: `execute()`'s `Applied`-only no-op fell through to `record()`, resetting `Undoing`/`Undone` -> `Pending`, destroying a pending undo and *resurrecting* a deliberately-undone mutation) and must preserve the durable `seq` (a regressed `seq` corrupts recovery order).
- **Pure decision + atomic claim; the claim is authoritative.** `classify` performs no mutation — mirroring a read-only `peek` ("no effect -> no resolve"). The durable *claim* of a `Fresh` key is the existing atomic `INSERT ... ON CONFLICT ... WHERE fingerprint-matches`. **If `classify` saw `absent` but another writer claims the key first, the atomic claim re-derives the real decision** (`TerminalReplay` / `Conflict` / `InProgress`) — `execute()` never dispatches on a stale `Fresh`. Pure table + authoritative atomic claim reconciles "testable truth table" with "no TOCTOU race."
- **`Conflict` and replay are evidenced, not silent.** A `Conflict` (a key-rewrite attempt — bug or key-reuse attack) emits an audit event, not just an `Err`; an idempotent terminal replay emits a lightweight "key replayed, no effect" marker (not a stored body) so an auditor can reconstruct execute-once-vs-twice. Wires into ADR-P008's evidence stream.
- **Ordering** (`fence -> replay-peek -> scope`): any future epoch/holder fence precedes the replay short-circuit; classification precedes record/dispatch.

**Failed-state semantics (named, not defaulted).** In M0 a connector failure is **transient-retryable by default**: the intent stays in its current non-terminal state for the next sweep (matching `recover()`, which is already correct) — it does NOT hard-enter `Failed`. **Implementing this ADR therefore requires changing `execute()`'s failure path to stop hard-entering `Failed`** (it did before this ADR was implemented) — a named behavior change, not just a `classify` consolidation. `Failed` is **reserved in M0**: the truth-table row states the full post-provider-slice contract; in M0 `Failed` is reached only by a corrupt/legacy row, and callers fail closed. It is the terminal **dead-letter** state for *deterministic* failures (validation, permission, missing target) and retry-budget exhaustion. Entering `Failed`, the retry cap/backoff, and dead-letter inspect/replay are deferred to the provider slice (a reserved shape, like the `ActionEnvelope` fields in ADR-P006/P007) — and are **required by ADR-P010's validation gate before any real-provider connector is enabled** (unbounded retry against a real provider is an enterprise-audit failure). This follows the mature literature: transient -> retry-with-cap; deterministic -> terminal dead-letter; append linked records, never erase. (Coupling: when `EvidenceSnapshotWritten` goes live, `recover()` — today matching only `Pending`/`Undoing` — must extend to it, or the table lists a state recovery cannot resume.)

**Status-set extension.** Three terminals join `Applied`/`Undone`/`Failed` in the P013 status domain: `Severed` — a control-plane seizure closed the operation (the kill-switch; a distinct terminal, never conflated with a provider failure); `Adjudicated` — an ISSUANCE-UNKNOWN attempt's OPERATIONAL axis was closed by an authority-gated in-place decision (the HISTORICAL attribution axis may permanently stay `UNKNOWN` — a late ack still resolves it, never re-authorizing dispatch); and `ExternallySatisfied` — a retry requalified against a moved provider and found the target state already held, so the attempt closed proven-no-wire and the operation never re-dispatched . All three are terminal, never pre-dispatch-eligible, and undo-INELIGIBLE with a NAMED, mechanical reason — never a guessed inverse (`prestate::UndoUnavailableReason::{Severed,Adjudicated,ExternallySatisfied}`, the undo-eligibility gate). The replay truth table above extends the same way: an identical-fingerprint replay against each returns its OWN truthful `Err` class — `Err(Severed)` / `Err(ExternallySatisfied)` / `Err(AdjudicatedUnresolved)`-class (an `AdjudicatedLate(Applied | RefusedNoEffect)`-class resolves the historical axis only, once a late ack arrives) — never the generic dead-lettered `Err(Failed)` and never a silent `Ok`. The undo presentation projection (`UndoPresentation`) surfaces each distinctly too: `ExternallySatisfied` (parent), `AppliedUndoUnresolved` (adjudicated undo child), and `AppliedUndoSevered` (severed undo child) are their own values, never folded into `AppliedUndoFailed` or a bare `None`.

**No stored response body (named divergence).** Stripe/brandur persist and replay the result body per key; Photon's bus returns `Result<(), ExecuteError>`, so terminal replay returns a no-op `Ok` (for `Applied`/`Undone`) or the failure outcome (for `Failed`) — **not** a cached body, and **not** a blanket `Ok` for every terminal state. Acceptable for an internal command bus — named here so no one later assumes Stripe-equivalent replay semantics.

**Deferred to the provider slice (named — ADR-P010's validation gate is the forcing function before any real-provider write; all M0-inert because the connector is a mock).** These are NOT five peers — they have a dependency structure, made explicit here so a future session does not cherry-pick a genuinely-blocked item and bake in a guess :
- (a) **[BLOCKED — unblock-gate: a real concurrency model / live I/O; nothing to build until then]** The **in-progress / 409 concurrency guard** for same-key concurrent `execute()` (masked in M0 by `execute(&mut self)` single-process serialization). **And (bound from ADR-P008's seizure carve-out): the concurrency model this item builds MUST include the kill-preemptible execute lock — a unilateral human seizure/kill is never lock-ordered behind a machine transition's evidence I/O. Closing this item with an ordinary shared lock does NOT discharge the ADR-P008 hung-machine-append residual; that residual stays open until preemption exists.**
- (b) **[BUILT — see `docs/design/2026-06-23-failed-dead-letter-design.md`. Mechanism built against a mock deterministic-fail connector: `FailureKind` (Transient|Deterministic) at the seam; deterministic failure dead-letters to `Failed` immediately; transient failure charges a durable `attempts` budget (`RETRY_CAP`) then dead-letters on exhaustion; `backoff_delay` is the reserved exponential-and-capped schedule (no clock/jitter wired yet); `dead_letters()` is the inspect surface. The error-policy taxonomy (which provider errors are deterministic vs transient) STAYS deferred to the connector, documented and NOT via a parked red test.]** The **`Failed` dead-letter lifecycle** — deterministic-failure classification, retry cap/backoff, inspect/replay.
- (c) **[BUILT — see `docs/design/2026-06-23-undo-tail-ordering-design.md`]** **Undo tail-ordering** — `undo()` dispatches its inverse immediately and only `recover()` carries a per-resource ordering barrier, so an undo can be re-defeated by a *later* same-resource intent left `Pending` (a consequence of the transient-retryable `Pending` rule); the fix makes undo its OWN tail-`seq` compensating intent (not a local deferral) so it sequences after all prior same-resource intents (the formerly-`#[ignore]`d test is now green). **Generalized after code review to the `TailOrderedMutationInvariant`: `execute()` defers behind a pending same-resource predecessor too (recorded `Pending`, returns `InProgress`), and `recover()` self-heals the original→`Undone` flip when a compensation terminalizes — closing a dual-write crash window (ExecuteOvertakesPendingResource + CompensationLinkageAtomicity).** **Scope fence:** ordering only — do NOT deepen the `inverse()`-is-a-clean-mirror assumption (the real connector meets irreversible/lossy actions; pluggable compensation-derivation is later work). **Reserved assumption:** the resource key is `(account, single message_ref)`; a future folder-scoped/bulk action needs a broader resource identity. **Later change: the deferred-undo `Undone`-at-scheduling behavior is superseded — undo is an operation kind through the classifier; the parent flips `Undone` at verification only; `Undoing` is a derived presentation.** (Consequences of that flip moving to verification: the undo child is admitted through this same classifier with its own frozen basis and its OWN retry budget — the compensation dead-letter exemption named above is DEAD, because it existed only to cover the pre-flip's lie — and a stored `undoing` row is now legacy-only, mapped back to the last verified truth by `recover()`.)
- (d) **[BLOCKED — unblock-gate: ADR-P008's evidence stream, not yet built]** **Evidence markers** for a `Conflict` (key-rewrite) and an idempotent replay — so the gate currently returns `Err`/`Ok` only.

**Why.** Repeated review findings on this area came from one invariant enforced at three drifting sites; consolidating it into one classifier removes the class. It is the canonical idempotency-key contract (Stripe / brandur.org / IETF `Idempotency-Key` draft) and the same shape as a read-only replay `peek` short-circuit. Enterprise procurement reads the audit trail — a system-of-record that silently mutated or resurrected a mutation is a disqualifying defect, not a P2.

**Rejected.** A shared *preflight helper* returning a bool / branching internally (doesn't kill the class — only an exhaustively-matched typed `Decision` does); a pure decision function with a separate caller-side write (reintroduces the TOCTOU race the atomic claim fixed); letting `record()` own status transitions; treating every connector failure as terminal `Failed` (conflates transient with deterministic — the inconsistency this ADR resolves); full Stripe-style response-body caching in M0 (over-scope for a `Result<(), ExecuteError>` bus); a `Decision` that carries raw `IntentStatus` a caller can wildcard (defeats the exhaustive-match guarantee); returning `Ok` for an in-flight or `Failed` identical retry (silent false-success — the audit trail must not lie in either direction).

**References.** Stripe idempotent-requests; brandur.org idempotency-keys; IETF `draft-ietf-httpapi-idempotency-key-header`; event-sourcing/CDC literature on append-don't-erase, dead-letter as a terminal class, and idempotent + duplicate-tolerant consumers.
